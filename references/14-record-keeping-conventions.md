# 14 · 档案仓库约定:布局、总控待办表、台账、commit 纪律、私有远程、敏感纪律、官网仓库公开约束

## 目标
一个 git 仓库就是公司的变更史:任何人(或下一个会话)读 `00-项目总控.md` 5 分钟就知道现在在哪、谁欠谁什么、下一步是什么。

## 1. 仓库布局(按编号目录,一专题一目录)
```
<company>-company/
├── CLAUDE.md                      # 仓库级规则(见 §6 模板)
├── 00-项目总控.md                  # 全局进度、决策记录、待办表、时间线
├── 01-决策与名称/                  # 账号与订单台账、中文名提案
├── 02-注册文件/                    # Certificate、Articles PDF、NUANS PDF、公司信息表、草案(标历史)
├── 03-公司治理/                    # Minute Book 01–11、签署打印包 html/pdf、固定资产台账
├── 04-税务/                        # CRA 指引、ITC 清单、所得税/薪酬/福利分析、确认信转录、凭证/<年>-Q<n>/
├── 05-品牌/                        # logo-交付包、命名提案
├── 06-网站/                        # README-上线步骤;site/ 为独立仓库,.gitignore 排除
├── 07-政府项目/                    # 优惠政策、融资调研、EOR 调研与询价全记录、合同包、招聘证据包、NDA-IP、SR&ED 模板
├── 08-Apple迁移/                   # 迁移前后清单、来电话术、证明信、个人期报告/
├── 09-LinkedIn运营/                # 运营手册(已发帖存档)
├── 10-支付/                        # 收款通道准备包、订阅台账
├── 11-保险/                        # 保单审核 + 保单/COI/AI 证书 PDF
├── 11-<海外子公司>/                # 筹办总控 + 00–16
└── 12-团队运营/                    # 工作记录制度、daily-log / release-log CSV
```
模板见 `templates/`。文件名用中文专题名 + 编号前缀;对外英文文件(决议、协议)文件名英文。

## 2. 总控文件结构(`templates/00-项目总控.md`)
1. 标题 + 顶部"当前实际阶段"一段(海外子公司类长期项目单独一段)。
2. 状态图例:⬜ 未开始 · 🔄 进行中 · ✅ 完成 · ✋ 需要你亲手操作。
3. **必须由你亲手操作的三类事情(安全边界)**。
4. **📌 当前总待办表**(更新日期):`# | 事项 | 状态/下一步 | 截止`;✋ 标亲手项;完成的行留一段时间再删,便于回看。
5. 🎯 当前运营重点(每 1–2 周一句话 + 3–5 条)。
6. 阶段章节(阶段 0 决策表 → 1 名称品牌 → 2 注册 → 3 Minute Book → 4 CRA → 5 运营配套 → 6 内部结构 → 7 Apple → 8 官网 → 9 政府项目 → 10 用工 → 11 保险 → 12 品牌与招聘阵地 → 13 收款 …),每条 ✅/🔄/⬜ + 日期 + 关键数字 + 文件链接;废弃路线标 ⚠️ 留档。
7. 决策记录(日期 + 结论 + 理由)。
8. 末尾免责一句。

## 3. 台账(11 §1)与状态词纪律
- 只写有证据的状态:研究/草稿/表单打开/用户选定 ≠ 受理/核准/签署生效/开户完成/已付款。
- 每条对外动作记:时间(时区)、发件地址、收件人、主题、版本、**由谁发出**(Claude / 用户)。
- 用户口头告知的事实标"(用户告知,凭证待补)"。
- 更正历史错误时保留更正痕迹("此前误记 X,2026-08-25 更正为 Y")。

## 4. commit / push 纪律
- **每完成一次实质变更(文件增改、对外动作落档、状态更新)立即 `git commit`**,消息一行中文摘要说清"发生了什么"(可带日期),正文列要点;**不要攒批量提交**——每条消息就是一件发生过的事,159 条提交 = 项目时间线。
- **每次 commit 后随手 push** 到 **PRIVATE** 远程(`github.com/<user>/<company>-company`);必须保持 private,不得公开或改可见性。
- 官网仓库(GitHub Pages)必须 **PUBLIC**,与档案仓库分开;档案仓库 `.gitignore` 排除 `06-网站/site/`。
- 委派 worker 时:worker 在仓库里直接提交,编排者 `git diff` / `git log` 审阅后再推送/发布。
- 附署格式按当前工具约定(如 `Co-Authored-By: …`)。

## 5. 敏感纪律
- **绝不写入任何文件**:密码、Company Key、网银凭据、借记卡号、2FA 恢复码、SIN、生日、家庭住址(ISC 登记册除外——它法定要含且私密存注册地址;若仓库副本要公开/复用先脱敏)、证件号、Apple/Stripe API 密钥。
- 台账只记"账号线索"(登录邮箱、用户名、2FA 方式、"密码在密码管理器")。
- 可以写:公司标识(BN、OCN、D-U-N-S、账号后四位)、公司地址电话、订单号——因为仓库私有;**但复用到别的公司/skill 时全部占位符化**。
- 电话指引里的个人信息一律改"如实口头答";误写立即抹除并 commit 说明。
- 对外邮件不附证件/流水;首轮不披露非必要数字。

## 6. 仓库 `CLAUDE.md` 模板(6 行够用)
```
# {{COMPANY_LEGAL_NAME}} — 公司筹建与运营档案库
- 全局进度、决策记录、待办看 **00-项目总控.md**;各专题看编号目录内的文件。
- 本目录是 git 仓库(<起始日>):每完成一次实质变更后立即 `git commit`,消息一行中文摘要;这是项目的变更史,不要攒批量提交。
- `06-网站/site/` 是独立仓库(GitHub Pages,push 即发布),已在 .gitignore 排除,勿在本仓库操作它。
- 敏感纪律:密码/Company Key/银行凭据一律不写入任何文件(台账只记账号线索)。
- 远程:github.com/<user>/<company>-company(PRIVATE);每次 commit 后随手 push;必须保持 private。
- 官网源码仓库 <user>/{{DOMAIN}} 保持 PUBLIC——GitHub Pages 免费版私仓不能建站,私有化=官网下线;想私有需 GitHub Pro 或迁 Cloudflare Pages,动之前先与用户确认。
```

## 7. 记忆(跨会话)
- 项目记忆一条:项目现状 + 关键决策 + "继续时先读总控从未完成阶段接着推进;账号/付款/提交由用户"。
- 用户画像一条:语言、省份、偏好("直接代办而不是只给指导")。
- 反馈类记忆:工具坑(如 Gmail 草稿 URL 包装),写 Why + How to apply。

## 坑与检查项
- ☐ 攒了一天再 commit → 时间线失真;每件事一条。
- ☐ 忘 push → 下一个设备/会话拿不到。
- ☐ 档案仓库误设 public / 官网仓库误设 private → 前者泄密、后者官网下线+Apple 撤回。
- ☐ 把总控里的旧待办表残留 → 定期清理合并。
- ☐ 用"已联系"代替"已发送并有回执" → 状态词纪律。
